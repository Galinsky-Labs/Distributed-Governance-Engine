# Previewed numbering settings

Legal numbering in the editor side panel lets an author choose US federal, corporate or decimal numbering. Select the document's top-level sections or the child sections of a particular section/exhibit, choose a starting ordinal, and optionally reserve increasing unique numbers. Other scopes retain their existing rules. Reserved lists are limited to 2,000 ordinals and 20,000 input characters. Starting at 1 with no reservations removes that scope's override. Invalid targets, duplicate/unsorted reservations, excessive depth and unrenderable Roman ordinals fail before application.

Preview shows old/new section labels and dependent references before changing source. Explicit reference labels keep their wording and are listed for review. Application preserves every semantic ID, exact body text, marks and reference target. Only numbering metadata changes; heading labels are derived. The existing authenticated document session saves a new version and reports persistence failures normally. Undo/redo restores the exact prior profile and rules, including the original absence of optional rules.

A preview is tied to the editor content and settings at preparation. Input changes or document changes clear it in the UI; the controller also refuses a stale, reconstructed or foreign preview. Selection-only navigation does not invalidate it. Prepared settings are detached from caller mutation. This is a local consistency check, not a signed policy decision or an authorization token.

These metadata edits are available in the ordinary editable draft only. The current live Yjs fragment synchronizes body nodes, not root metadata: live controls explain that authors must exit live editing, and a transaction filter refuses root numbering changes in that editor. Existing historical Yjs roots without attributes read the trusted version's numbering metadata. An ordinary authenticated save still advances the expected document version; it cannot silently modify another participant's active source version. Published, adopted, signed, public-input and view-only editors retain their existing direct-edit barriers.

The ProseMirror adapter carries the numbering profile, rules and explicit rules-presence marker on its internal document root so history can restore missing optional metadata correctly. These editor attributes are not new semantic-schema fields. The portable schema, tenant/document identity, mode/lifecycle authority, hashing domains and database schema remain unchanged. The existing `previewLegalNumbering` and `applyLegalNumberingRules` functions accept an optional third `{numberingProfile}` argument; existing calls retain their original default profile.

Tests cover detached preview/affected-reference output, stable content, one-step undo/redo, restoring absent and existing rules, stale preview rejection, selection stability, invalid profiles/rules, immutable/read-only guards and legacy/live-root behavior. The authenticated Chromium journey previews and applies numbering, checks semantic body equality, saves/undoes/redoes/reopens, rejects invalid reservations, invalidates a preview after typing, joins/exits the actual public WSS editor, checks 320-pixel reflow and freezes source. Its signed fixture OIDC and PGlite database are not production-provider or cloud deployment acceptance.

No new credentials, dependencies or migrations are required. This is a partial DCE-006 contribution; deleted-section workflows, broader jurisdiction profiles, live metadata synchronization, typed package migration and complete production/assistive-technology acceptance remain separate work.

[Section hierarchy](SECTION_HIERARCHY.md) supplies the separate previewed indent/outdent controls for ordinary drafts.

The additional `referenceChanges` preview field tracks complete reference paths, including a changed parent whose child keeps the same local label. The UI uses these impacts; existing local-heading preview fields remain available. See [Internal references](INTERNAL_REFERENCES_EDITOR.md).
