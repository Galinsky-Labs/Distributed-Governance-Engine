# Previewed section indent and outdent

Select text within one section to use Section hierarchy in the editor side panel. Preview indent moves the section inside the preceding sibling section; intervening unnumbered blocks stay in their existing parent. Preview outdent moves a nested section after its parent, within the grandparent document, section or exhibit. The preview names the source and destination, lists changed section labels and dependent references, and reports remaining reference issues. Explicit reference labels retain their wording and require review.

No move occurs until Apply section move. The command preserves semantic IDs, exact text, marks, tables and reference targets, performs minimal delete/insert steps, and restores the cursor/range within the moved section. The existing semantic move validator rejects invalid destinations, cycles, unrenderable numbering depth and moves that would leave a required parent empty before ProseMirror constructs a transaction. The first sibling cannot indent and a top-level section cannot outdent. Selecting across different nearest sections does not choose one implicitly.

Prepared previews are private local handles tied to the originating editor and exact source content. A changed source, cloned/foreign preview or selection in another section cannot apply. The user may move the cursor within the previewed section; the command preserves its current offset. The UI also clears its preview when the source or selected section changes. This local consistency mechanism is not an authorization token or signed governance decision.

A move forms one undoable structural change and uses the existing authenticated autosave/version path. Undo/redo and reopening retain stable IDs. Immutable or view-only sources cannot move directly. The controls and prepared command are unavailable in the live fragment editor; ordinary live text editing does not gain an operation that claims safe concurrent subtree moves. A future shared hierarchy protocol must address edits to a subtree while it moves. Private editing remains disabled by the existing independent encryption/device requirements.

Model tests cover label/reference and destination previews, exact domain-model equivalence, unchanged block identity/text/marks, selection offsets, undo/redo, stale/foreign previews, cross-section selection, invalid moves, empty-parent protection, exhibit destinations and maximum hierarchy depth. The authenticated browser journey moves/undoes/redoes/outdents, compares stored source and IDs, reopens, invalidates a preview after typing, exercises actual WSS join/exit, verifies 320-pixel reflow and freezes source. Signed fixture OIDC and PGlite with local TLS do not establish hosted production or assistive-technology acceptance.

No credentials, dependencies, semantic schema fields or database migrations change. The source metadata and numbering reservations remain intact. Deleted-section reservation/tombstone workflows, additional jurisdiction profiles, typed package migration and full operational acceptance remain separate DCE-006 work.

CI runs the same complete browser glob with Node's spec reporter and an additional annotation reporter. Failure annotations contain only the test name, exception type and source-file location; they omit assertion values, stack contents, fixture data and document text. The original job logs retain their existing access controls. A failed test still exits nonzero; no assertions or required checks are skipped.
