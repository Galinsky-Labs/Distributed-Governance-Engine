# DCE-033: Accessibility, localization and low-bandwidth clients

Status: partial. PR #69 contributed localization (en, es, fr, ar), RTL direction and keyboard-first panels; the accessibility increment adds an automated axe-core (WCAG 2.0/2.1/2.2 A and AA tags) audit of rendered governance, sign-in, verify and language UI in jsdom, with a positive control, plus a keyboard-reachability and accessible-name check. Colour contrast, target size, reflow, text scaling and manual screen-reader checks are not automated here and have not been recorded.

## Problem and resulting behavior

Meet WCAG 2.2 AA target with manual keyboard/assistive checks, plain-language help, localization, bidirectional text and read-mostly low-bandwidth pages.

## Data migration, rollout and rollback

Use expand/contract migrations and scoped feature flags. Reconcile old/new records before switching readers. A rollback must preserve ballots, signed editions, audit history and receipts; never rewrite an adopted or signed version. For work without persistent schema changes, record that fact with the final diff. If a release changes authority, eligibility or cryptographic boundaries, add an ADR and a tested migration path.

## PR and completion protocol

Use leading stable ID `DCE-033: ...`; link this unit and explicit dependencies. Map only real PR numbers into registry/prs.json. Require current-head CI and the checked-in merge preflight before authorized merging. Failed, missing, pending or skipped required checks remain blockers. Human review and independent certification are deferred until the deployed result is ready for the owner; concrete vulnerabilities and failing tests are not waived. Merged source, tested code, deployment and live operational acceptance are separate states.
